# What is a CSRF Token?

## Overview

A CSRF token is a security mechanism used to protect web applications against Cross-Site Request Forgery attacks.

The token is generated by the server and shared with the client. When a user performs a sensitive action, the application verifies that the correct token is included in the request.

Without a valid token, the request is rejected.

---

# Definition

A CSRF token is a:

```text
Unique
Secret
Unpredictable
```

value generated by the server-side application.

---

# Purpose of CSRF Tokens

The primary goal of CSRF tokens is to ensure that requests originate from legitimate users and not attacker-controlled websites.

---

# Why Tokens Are Needed

Consider a normal request:

```http
POST /my-account/change-email HTTP/1.1
Cookie: session=abc123

email=user@example.com
```

An attacker can easily recreate this request.

---

# Protected Request

```http
POST /my-account/change-email HTTP/1.1

csrf=50FaWgdOhi9M9wyna8taR1k3ODOR8d6u
email=user@example.com
```

Now the attacker must know the token value.

---

# How CSRF Tokens Work

## Step 1

Server generates token:

```text
50FaWgdOhi9M9wyna8taR1k3ODOR8d6u
```

---

## Step 2

Server sends token to browser.

---

## Step 3

Browser includes token in future requests.

---

## Step 4

Server validates token.

---

## Step 5

Request accepted only if token is valid.

---

# Common Token Placement

Most applications place tokens inside hidden form fields.

---

## Example

```html
<form action="/my-account/change-email" method="POST">

<input type="hidden"
name="csrf"
value="50FaWgdOhi9M9wyna8taR1k3ODOR8d6u">

</form>
```

---

# Request Generated

```http
POST /my-account/change-email

csrf=50FaWgdOhi9M9wyna8taR1k3ODOR8d6u
email=test@example.com
```

---

# Characteristics of Secure Tokens

A secure CSRF token should be:

| Property | Description |
|-----------|------------|
| Unique | Different users receive different tokens |
| Secret | Hidden from attackers |
| Unpredictable | Cannot be guessed |
| Session Bound | Linked to user session |

---

# Why Attackers Cannot Easily Bypass Tokens

An attacker can create:

```html
<form>
```

but cannot predict:

```text
50FaWgdOhi9M9wyna8taR1k3ODOR8d6u
```

Without the correct token:

```text
Request Rejected
```

---

# Tokens Are Not Always Hidden Fields

Some applications send tokens using:

```http
HTTP Headers
```

Example:

```http
X-CSRF-Token: token123
```

---

# Token Transmission Methods

| Method | Example |
|----------|---------|
| Hidden Form Field | Most common |
| Request Header | APIs |
| Request Parameter | Query strings |
| Cookie | Sometimes used |

---

# Single-Use Tokens

Some applications generate:

```text
One-Time Tokens
```

After use:

```text
Token Invalidated
```

This provides additional protection.

---

# Session-Bound Tokens

The most secure implementations bind:

```text
User Session
        ↓
CSRF Token
```

A token from another user should never be accepted.

---

# Common Token Validation Workflow

```text
User Requests Form
        ↓
Server Generates Token
        ↓
Token Sent To User
        ↓
User Submits Form
        ↓
Token Validated
        ↓
Request Accepted
```

# Key Takeaways

- CSRF tokens are the most common CSRF defence.
- Tokens must be unique, secret, and unpredictable.
- Session-bound tokens provide stronger protection.
- Attackers should never be able to predict token values.

> [!IMPORTANT]
> CSRF protection is only effective when token validation is implemented correctly.
