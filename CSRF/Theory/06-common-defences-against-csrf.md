# Common Defences Against CSRF

## Overview

Modern web applications use multiple layers of protection to defend against CSRF attacks.

The goal is to ensure that requests originate from legitimate users and not attacker-controlled websites.

---

# Primary CSRF Defences

The most common CSRF protections are:

1. CSRF Tokens
2. SameSite Cookies
3. Referer Validation
4. Origin Validation

---

# 1. CSRF Tokens

A CSRF token is:

```text
Unique
Secret
Unpredictable
```

and generated by the server.

The token must be included in sensitive requests.

---

## Example

```html
<input type="hidden" name="csrf" value="token123">
```

---

# Why Tokens Work

An attacker cannot predict the token value.

Without the correct token:

```text
Request Rejected
```

---

# 2. SameSite Cookies

SameSite is a browser security feature that controls when cookies are sent in cross-site requests.

---

## SameSite=Strict

```text
Never send cookies cross-site.
```

Strongest protection.

---

## SameSite=Lax

```text
Limited cross-site cookie sending.
```

Modern browser default.

---

## SameSite=None

```text
Cookies sent normally.
```

Weakest protection.

---

# 3. Referer Validation

Applications may verify:

```http
Referer
```

header values.

---

## Example

```http
Referer: https://normal-site.com/profile
```

If the request originates elsewhere:

```text
Request Rejected
```

---

# Limitations

Referer headers:

- can be missing
- can be manipulated
- are less reliable than tokens

---

# 4. Origin Validation

Applications verify the:

```http
Origin
```

header.

---

## Example

```http
Origin: https://normal-site.com
```

Only trusted origins are accepted.

---

# Why Multiple Defences Are Better

Applications should not rely on a single protection mechanism.

Best practice:

```text
CSRF Token
+
SameSite Cookie
+
Origin Validation
```

# Key Takeaways

- CSRF tokens are the strongest defence.
- SameSite cookies add browser-level protection.
- Origin validation is generally stronger than Referer validation.
- Multiple defences should be combined.

> [!IMPORTANT]
> Most modern CSRF attacks involve bypassing these protections rather than exploiting applications with no defences.
